### 3.3 入力検証（XSS・意図しない読み込み）

- `innerHTML` の使用は全 9 箇所で、**すべて `= ""`（中身を空にする）だけ**。ユーザー入力を HTML として挿入する箇所はない。表示は `textContent` / DOM API。`outerHTML` は Leaflet のピン（クラス名は固定のカテゴリ、中身は数字）のみで、既存の `test-css-xss.js` も通る。
- `eval` / `new Function` / `document.write` / `window.open` / `location` への代入は 0 件。
- リンクの `href` は `isSafeHttpUrl`（`http(s)://` のみ。`javascript:` は通らない）か、固定の Google マップ URL からの組み立て。`target="_blank"` には `rel="noopener"`。
- 実行時の外部通信先は、コード内の固定定数のみ（OSM タイル・Nominatim・Google Maps Platform・Firebase）。**ユーザー入力から外部 URL を取得する箇所はない**（短縮リンクを展開しない設計）。
- 共有リンク `#d=`: 確認ダイアログ → `normalizeTrip`（型・範囲を正規化）→ 新しいしおりとして追加。`#p=` / `#e=` の ID を **検証するようにした**（S-1）。
- CSV 取り込み: 文字単位のパーサで、コードの実行はない。**書き出し時の数式インジェクション（Excel で開くと `=…` が実行される）に対策した**（S-2）。
- 残り: **CSP（Content-Security-Policy）が無い**（防御の追加層）。Firebase の Google ログインが読み込む先が多く、実ブラウザで確認しないと壊すおそれがあるので入れていない（§7）。

### 3.4 Node.js CVE-2026-111497（Brotli デコーダ、CVSS 9.2）

- 修正版: 22.23.4 / 24.22.1 / 26.12.1。20.x は EOL で修正なし。複数のセキュリティ解説記事で確認した（Node.js 公式の告知本文そのものは未確認。一次情報として公式の告知も見てほしい）。
- **CI は Node 20 だった → Node 24 に変更**し、修正版未満なら失敗するステップを追加した。
- このアプリ本体は静的ファイルでブラウザ上で動くので、Node の脆弱性の影響を受けない。影響はテストを動かす CI・開発者のマシンだけ。開発者のマシンの Node も更新してほしい。
